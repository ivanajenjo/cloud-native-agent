# ADR-0005: Migrar a Pi 1.x (`@earendil-works/pi-coding-agent`)

- Estado: aceptado
- Fecha: 2026-11-16

## Contexto
El plan fijaba `@mariozechner/pi-coding-agent@0.73.1` (mayo de 2026). Ese paquete está
deprecado en npm en favor de `@earendil-works/pi-coding-agent`, que va por la `1.5.2`.
Todavía no hay código escrito, así que migrar ahora no cuesta nada y hacerlo después
obligaría a rehacer el bridge y las extensiones.

## Decisión
Usar `@earendil-works/pi-coding-agent` con versión exacta `1.5.2`.

## Cambios que afectan al diseño
- **Node ≥ 22.19.**
- **Fin de ejecución:** `agent_end` ya no significa que Pi haya terminado (puede
  reintentar, compactar o seguir con la cola). La señal es `agent_settled`.
- **Streaming:** `message_update` solo trae deltas; el mensaje completo llega en `message_end`.
- **`prompt`** responde con `data.disposition` (`started`, `queued` o `handled`).
- **Canal extensión → cliente:** `pi.appendEntry()` se emite por RPC como `entry_appended`.
- **Project trust:** los recursos ejecutables del repo (`.pi/extensions`, `.pi/settings.json`,
  `.pi/mcp.json`, `.pi/SYSTEM.md`, skills) requieren confianza. En RPC no hay diálogo;
  arrancamos con `--no-approve` para rechazarlos siempre de forma explícita.
- **MCP:** Pi ya lo soporta. Lo desactivamos con `--no-mcp` (ver plan, descartado).
- **Esquemas de tools:** se validan como JSON Schema; las funciones de TypeBox que no son
  JSON Schema (`Type.Refine`, codecs…) no se aplican. `Type` se importa de `typebox` y
  `StringEnum` de `@earendil-works/pi-ai`.
- **RpcClient:** ahora se exporta, pero sin soporte de diálogos (ver ADR-0002).
- Comandos RPC nuevos útiles: `get_entries`, `get_tree`, `clear_queue`.

## Consecuencias
- (+) Partimos de una versión mantenida y con documentación de seguridad y contenedores.
- (−) Lo validado contra la documentación de 0.73.1 hay que releerlo en la de 1.5.2 antes
  de implementar cada pieza; `AGENTS.md` obliga a ello.
